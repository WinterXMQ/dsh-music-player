# 新闻播报 · UI / 交互设计

> 范围：`docs/daily-news-briefing-design.md`（已确认）中 Web 端部分的界面与交互定稿。
> 原则：新闻是「讲书家族」的第二个成员——**凡讲书已有的交互心智，一律原样继承**；
> 新闻特有的只有两处新界面：面板「新闻播报」页签、播放条的类别目录弹层。
> 状态：已确认。

## 1. 设计原则

1. **复用讲书心智**：类别 = 章节、期次 = 一本书、条目 = 句子。用户学会过 AI 讲书，就会用新闻播报，零学习成本。
2. **播报为主、阅读为辅**：声音是主出口；面板文字版用于「错过了/想细看/想挑着听」。
3. **不新增视觉语言**：全部复用现有样式类（`.dsh-music-tab` / `.dsh-music-track` / `.dsh-music-toc` / ghost 按钮等），不引入新颜色与新组件范式。

## 2. 入口与信息架构

面板左侧竖排页签（`.dsh-music-tabs`，88px）插入「新闻播报」，位置在 **AI讲书之后、系统配置之前**：

```
┌────────┐
│ 本地音乐 │
│ QQ音乐  │
│ 酷狗音乐 │
│ AI讲书  │
│ 新闻播报 │  ← 新增（active 态高亮同现有）
│ 系统配置 │
│ 关于    │
└────────┘
```

- 新闻页签**不显示** `DirectorySetting`（目录选择行，新闻无目录概念），与 qq/kg/config/about 同规则。
- 内容 pane 常驻渲染 + `display:none` 切换（`paneStyle('news')`），保持与其它页签相同的状态保留策略。

## 3. 面板「新闻播报」页签（两层结构）

### 3.1 第一层：定时状态行 + 期次列表

期次列表上方新增一条**常驻「定时」状态行**（定时规则的入口与状态摘要）：

```
┌──────────────────────────────────────────────┐
│  ⏰ 每日定时  08:00 播报 · 12:30 静默 · 18:00 播报 › │   ← 定时状态行（常驻）
│ ────────────────────────────────────────────  │
│  ● 今天 · 18:00        [▶ 播放]              │   ← 今日最新一期，置顶；「●」=今日已生成
│    热点 5 · 国内 3 条 · 国际 3 · 科技 3           │   ← 类别 chips（小字次要色）
│  ──────────────────────────────────────────  │
│  昨天 · 09:00                                 │
│    国内 4 条 · 国际 3 · 科技 3 · 财经 3          │
│  05-28 · 09:00                               │
│    …                              [🗑]       │   ← 行尾悬停出现删除（二次确认）
└──────────────────────────────────────────────┘
```

- **定时状态行**：左「⏰ 每日定时」，中间摘要（各班次时刻 + 是否勾选「收集后立即播放」，
  如 `08:00 播报 · 12:30 静默`），右「›」进入定时规则编辑器（§4）。未设置时摘要显示
  「未设置 · 点击配置」。
- **收集与播放分离的展示约定**：无论班次是勾选播放还是静默收集、也无论是对话还是定时产生，
  **收集结果一律进入本列表**（一期一行）。静默收集产生的、尚未播放过的期次标「待播」徽标
  ——这就是「收集好的数据列表」，用户从这里选择某一期播放（点行进详情，可播整期、播某类、
  或点某一条新闻单独播）。
- **多任务混合展示**：不同班次/手动触发的期次在列表中**按时间倒序混排**，靠期次标题
  （如「AI 新闻简报」vs「早间新闻播报」）与类别 chips 自然区分；v1 不做按任务分组或筛选
  （保留策略上每组独立 7 期，见功能设计 §3）。
- 每行：日期时间（今天显示「今天 · HH:MM」，更早显示「MM-DD · HH:MM」）+ 类别/条数 chips；整行可点进入详情。
- 「▶ 播放」直接开播该期（等价于点进详情后的播放整期）。
- **今日徽标**：当天已生成期次的第一行行首显示「●」主题色圆点；若当期**尚未播放过**，
  圆点旁附「待播」小徽标（开播后消失）——覆盖「定时/静默收集时浏览器没开」与
  「静默收集后用户补播」两类场景。
- 空态（居中，`.dsh-music-empty` 同款）：

```
还没有新闻简报。
在对话框对我说「播报今天的新闻」即可生成；

也可以说「每天早上 9 点播报新闻」设置每日定时。
```

### 3.2 第二层：期次详情

进入方式：点击期次行。左上「← 返回」回到列表（同 QQ 面板的 head 返回模式）。

```
┌──────────────────────────────────────────────┐
│ ← 返回          今日新闻播报 · 05-30 09:00     │   ← head 固定不滚
│            [▶ 播放整期]  [🗑 删除]              │
│ ┌──────────────────────────────────────────┐ │
│ │ 国内要闻（3）                        ▶    │ │  ← 类别头：点击 ▶ 从该类第一条开播
│ │  1. xxxxx通过xxxx决议                     │ │  ← 条目行：序号 + 标题
│ │     新华社 · 摘要首行截断…                │ │  ← 来源 + summary 单行省略（次要色小字）
│ │  2. …                                    │ │
│ │ 国际（3）                            ▶    │ │
│ │  4. …                                    │ │
│ │ …（滚动区，只有条目列表滚动）                │ │
│ └──────────────────────────────────────────┘ │
└──────────────────────────────────────────────┘
```

- **条目行点击 = 跳播**：从该条目对应的音频块开始播（条目 ↔ 块映射 `itemChunk[]` 由 Host meta 提供）；正在播的条目行高亮（同歌单正在播样式）。
- **类别头 ▶**：从该类别第一条开播（等价讲书跳章）。
- 「▶ 播放整期」：从开场白开播。
- 删除：二次确认弹窗（复用 `ConfirmModal`）；正在播放的期次被删除则先停止播放。
- 若条目正在合成中，对应行尾显示迷你「合成中…」；失败显示「⚠ 重试」。
- **「文字版」按钮**（head 行，播放整期旁）：进入文字版阅读视图（§3.3）。

### 3.3 文字版阅读视图（详情页「文字版」进入，push 子视图）

不方便听语音时直接读——由结构化数据（`categories/items`）实时渲染的文章版，
非口播稿（开场白/过渡语是口语冗余，阅读版不要），跟随面板主题：

```
┌──────────────────────────────────────────────┐
│ ← 返回        早间新闻播报                     │
│   2026年5月30日 08:00 · 12 条 · 约 4 分钟      │   ← 元信息行（次要色）
│ ──────────────────────────────────────────  │
│  国内要闻                                     │   ← 类别小节标题
│  1. xxxxx通过xxxx决议                         │
│     摘要完整展示（两三行，不截断）。              │
│     —— 新华社 · 08:02                        │   ← 来源行（次要色）
│  2. …                                        │
│  AI                                          │
│  5. …                                        │
│  ──────────────────────────────────────────  │
│  由 AI 自动收集整理，内容以来源报道为准。          │   ← 尾注（免责 + 生成时间）
└──────────────────────────────────────────────┘
```

- **条目序号全局连续**（与播报顺序一致）；播放中打开此视图时，正在播的条目同步高亮，
  点条目 = 跳播（与详情页行为一致）。
- 摘要完整展示不截断；来源行含来源名与可选发布时间；类别小节标题分隔。
- 返回详情页保留滚动位置；此视图纯阅读，无音频控制。

│    简报」会话里同步（隔离收集历史）。               │

### 4.1 交互细节

- **班次行**：时间为 `<input type="time">`（步进 1 分钟）；**「收集后立即播放」勾选框，
  默认勾选**——勾选 = 到点收集并自动开播（`autoplay:true`）；不勾选 = **静默收集**
  （只生成/更新期次不出声，进入待播列表，见 §3.1）。行尾 [▶] **立即执行**、[🗑] 删除
  （至少保留一个班次才可启用）。
- **立即执行（▶）**：按**该班次当前的配置**（收集范围、是否勾选立即播放）立刻跑一轮，
  不等时刻；期次标题按当前时段与范围命名。因面板无直达会话通道（见 §4.2），点击后弹
  确认气泡：一键复制形如 *「立即执行我的 12:30 新闻班次：只收集科技与 AI 相关头条，
  收集完不播放」* 的精确指令，用户发送给 agent 后立即按规则执行（走 `news_broadcast`）。
  **连点多次无副作用**（按钮仅复制，5 秒内重复点击只 toast 一次）；同一班次冷却窗
  （10 分钟）内重复执行会被工具层跳过并提示，`force` 指令可强制重收（见功能设计 §5.1）。
- **添加班次**：追加一行默认 `08:00 · 勾选立即播放 · 继承默认类别`；上限 6 个
  （成本与可读性平衡，超出置灰）。
- **收集范围（班次级，点班次行展开）**：
  - **预设类别 chips**：热点（排第一，跨领域+热度排序）/ 国内 / 国际 / 科技 / 财经 / 体育 多选；
  - **自定义主题**：自由文本 tag（如 `AI`、`新能源汽车`、`美股`），每班次 ≤ 5 个。
    主题词双重语义——**搜索关键词**（agent 以「日期 + 主题 + 新闻」组合查询）与
    **期次类别名**（期次里出现以主题命名的类别，来源优先该主题的权威垂直媒体，
    如 AI → 机器之心 / 量子位，见功能设计 §8.3）；
  - **继承与重置**：未自定义的班次继承「默认类别」；自定义后覆盖并高亮「已自定义」，
    「重置为默认」恢复继承。
- **默认类别行**：全局兜底范围（chips + 自定义主题），仅被未自定义的班次继承。
- **保存**：写入 Host 端定时偏好（`POST /dsh-music/news/schedule`，持久化在 prefs）。
  保存成功 toast「已保存」。
- **同步状态行**：三态——`未设置` / `已同步 · N 班次` / `有未同步的修改`。
  v1 通过对比「偏好版本号」与「最近一次同步记录的版本号」计算（本地面板自持状态，
  不校验 DSH schedule 实际存在与否）；点「同步状态」弹出与 §4.2 相同的同步指引。
- **总开关关闭**：保留配置、摘要显示「已停用」；同步后 agent 删除全部新闻定时任务。

### 4.2 生效通路（面板 → agent → DSH schedule）

DSH 的 schedule 是 **agent 侧工具**，面板（客户端半体）没有直达会话的消息通道，因此
采用「偏好 + 同步」两段式，分两期实现：

- **v1（随 M3 落地）——提示词同步**：
  1. 面板保存偏好到 Host（prefs）；
  2. 插件的系统提示词 section **动态携带当前定时偏好**（每次会话请求重渲染）：
     「用户已在面板配置新闻定时偏好（尚未同步 / 已同步）：每天 08:00 收集后立即播放、
     12:30 仅静默收集，类别默认。当用户要求同步/应用新闻定时，或偏好与已建 schedule
     不一致时，用 `schedule_create` / `schedule_delete` 使实际定时任务与偏好一致
     （静默班次的提醒内容注明 `autoplay:false`），并汇报结果。」
  3. 用户对 agent 说「同步新闻定时」（编辑器底部 ⇱ 一键复制该指令）→ agent 增删
     schedule 至与偏好一致 → 在会话里回报创建了哪些；
  4. 同步完成后 agent 通过 `news_schedule` 工具（action:`markSynced`）回写同步版本号，
     面板状态行翻为「已同步」。
- **v2（M4 深度集成，可选）——直写 schedule**：插件 Host 端注入 sessions/agents 服务，
  直接在根会话事件日志追加 `schedule/change` 记录（依赖 `@deepseek-ai/dsh-schedule` 的
  记录构造器），并可由插件驱动一个**专用的「新闻简报」headless 会话**承载全部收集轮次
  （彻底不污染任何用户会话、UI 保存即生效）；代价是与 harness 内部记录格式/版本耦合。
  v1 验证需求后再评估。

> 为什么不做「面板直接创建定时任务」：client 插件只有 `slots` 注入与自身 HTTP 路由，
> 无会话消息 API；硬造通道会绕开 DSH 的会话/调度语义。两段式把「配置」放面板（可视化、
> 可发现），把「执行」留给 agent（复用现成 schedule 工具与生命周期管理）。

## 5. 播放条新闻模式

当前曲目 id 形如 `news:<editionId>` 时进入新闻模式（`isNews`），条形外观与讲书同构：

```
┌──────────────────────────────────────────────────────────────────────┐
│ 📰 今日新闻播报 - 国内要闻          [展开控件时→] 34%  ⏮ ⏯ ⏭ ⏹ 📖 🔊 ☰ │
│    ~~~~~~~~~~~~~~~~字幕逐句滚动区（闲置态显示）~~~~~~~~~~~~~~~~~~~~~~~~~  │
│ ▁▂▃ 进度细线：已读字符 / 全期字符（讲书同款，只增不减）                    │
└──────────────────────────────────────────────────────────────────────┘
```

控件映射表（对照讲书）：

| 控件 | 音乐模式 | 讲书模式 | **新闻模式** |
|---|---|---|---|
| 名称前图标 | 音符 | 话筒 | **报纸（📰 内联 SVG，同尺寸 currentColor）** |
| 名称行 | 歌名 | 小说名 - 章节名 | **期次标题 - 当前类别名**（次要色 `- 类别`，同章节拼接样式） |
| ♥ 收藏 | 有 | 隐藏 | **隐藏**（新闻不收藏） |
| ⏮ / ⏭ | 上一首/下一首 | 上一章/下一章 | **上一类 / 下一类**（title 相应写「上一类/下一类」） |
| ⏯ / ⏹ | 播放暂停/停止 | 同 | 同（无差别） |
| 📖 目录按钮 | 无（显示播放模式▾） | 章节目录 | **类别目录弹层**（见 §6）；隐藏播放模式下拉 |
| 🔊 音量弹层 | 音量滑块 | AI 声音 + 音量 | **AI 声音 + 音量**（复用 `VoicePicker`，切声音即重合成当前块，缓存 key 含 voice） |
| 频谱 | 有 | 无 | **无**（与讲书一致，保持「语音内容无频谱」的家族规则） |
| 时长区 | `01:23 / 04:56` | `N%` | **`N%`**（已读字符占比） |
| 进度细线 | position/duration | 已读/全书字符 | **已读/全期字符** |
| 字幕 | 歌词 | 逐句滚动 | **逐句滚动**（块文本 → 句子切分逻辑原样复用） |
| 合成状态 | — | `合成中… Ns`（BookStatus） | **复用 BookStatus**（含失败原因 + 重试按钮） |
| 自动播放拦截 | `⚠ 点击▶解锁` | 同 | 同 |

> 名称行 title 悬停显示完整「期次标题 - 类别」，与现有行为一致。

## 6. 类别目录弹层（📖）

复用 `BookTocPanel` 的结构/定位/样式（`.dsh-music-toc`，锚定按钮正上方，可变高）：

```
   ┌──────────────────────────┐
   │ 类别目录                  │
   │  ● 国内要闻    3 条  08:12 │   ← ● = 正在播的类别（active 高亮）
   │    ├ 1. xxxxx决议…        │   ← 类别下展开该类条目标题（当前条目再高亮）
   │    └ 2. …                │
   │    国际        3 条  07:40 │   ← 点类别行 → 跳该类；点条目行 → 跳该条
   │    科技        3 条  08:05 │
   │    …                     │
   └──────────────────────────┘
```

- 每行右侧显示该类累计时长估计（由块数 × 平均块时长，合成前可用字符占比估算，取不到则只显条数）。
- 打开即滚动定位到当前类别并高亮（讲书目录已有同款逻辑）。

## 7. 关键交互流

**流 A · 对话即时播报（主路径 = 收集完即播）**
```
用户:「播报今天的新闻」
 → agent web_search×N + 整理 → news_broadcast 工具（收集完立即播放，对话触发恒为 autoplay:true）
 → Host 持久化期次 + pendingIntent{kind:'news'}
 → 客户端 intent 轮询命中：加载 meta → 播放条切新闻模式 → 从开场白开播
 → 面板若已打开：自动切到「新闻播报」页签并进入该期详情（条目高亮跟随播放）
   面板未打开：不强行弹开，播放条已有完整反馈
```
对话中也可以只要收集不播放：「收集一下今天的新闻，先别播」→ agent 提交时
`autoplay:false` → 期次进入列表标「待播」，用户随时从面板选择播放。

**流 B · 每日定时（浏览器开着）**：同流 A，起点是 schedule 提醒驱动的 agent；播放与否由
该班次「收集后立即播放」勾选决定——勾选则播（同流 A），不勾选则静默收集后期次标「待播」。
聊天区会出现本轮收集的整理过程，用户可在会话里追问「把科技去掉了，重新播」→ agent 重新提交 → 同一期次被替换重播。

**流 B′ · 面板配置定时（与流 B 的衔接）**：
```
第一层点「⏰ 每日定时 ›」→ 定时规则编辑器：加/删班次、勾选「收集后立即播放」（默认勾选）、点「保存」
 → 偏好写入 Host；同步状态行变「有未同步的修改」
 → 用户对 agent 说「同步新闻定时」（或点 ⇱ 复制指令后粘贴）
 → agent 按偏好 schedule_create / schedule_delete（不勾选的班次提醒内容注明静默收集），回报结果并回写同步版本号
 → 状态行翻「已同步 · N 班次」；此后每个班次到点走流 B
```
注意：同步动作请在**专用「新闻简报」会话**（推荐）或常驻主会话里做——定时任务与每轮
收集都归属并发生在创建它的会话里（DSH schedule 会话级生效，见功能设计 §7.5），
专用会话可让收集历史不污染主工作会话。

**流 C · 错过/回看（收集好的数据列表）**：打开面板 → 新闻播报页签 → 列表里「待播」徽标的期次
（定时没听到 / 静默收集的都在这）→ 点行进详情 → 点「▶ 播放整期」，或点类别 ▶ 播某类，
或点某一条新闻从该条开始播。

**流 D · 播放中操作**：📖 跳类 / ⏮⏭ 换类 / 🔊 换声音（当前块重合成后无缝续播，断点字符位置不变）/ ⏹ 停止；刷新页面后期次与块位置从 prefs 恢复（讲书同款断点续播），播放条立即显示 `N%` 进度。

**流 E · 定时任务手动立即触发**：
```
定时规则编辑器里某班次点 [▶ 立即执行]
 → 弹确认气泡，一键复制该班次的精确执行指令（含类别与是否立即播放）
 → 用户粘贴发送给 agent → agent 立即按该班次配置跑一轮（收集 + 按勾选决定是否播放）
 → 期次照常入列表；若勾选播放则同流 A 开播
```
与定时触发的唯一差别是不等时刻、由用户手动拉起；配置不需先「保存/同步」也可立即执行
（按编辑器当前未保存的值执行）。

## 8. 状态与反馈汇总

| 状态 | 呈现位置 | 形式 |
|---|---|---|
| TTS 未配置 | 新闻页签顶部 | 提示条「未配置 xiaomi 提供方，简报可阅读不可播」（期次仍生成） |
| 块合成中 | 播放条名称后 + 条目行尾 | `合成中… Ns` 递增计数 |
| 块合成失败 | 播放条 | 错误文案 + 「重试」按钮（讲书同款） |
| 待播 | 期次列表行 | 「待播」小徽标（已收集未播放：定时错过/静默收集），开播后消失 |
| 班次执行中 | 定时状态行 + 编辑器班次行 | `⟳ 收集中…`（▶ 按钮禁点，TTL 10 分钟自动复位）；完成后出期/报失败 |
| 班次收集失败 | 定时状态行下方 | 「⚠ 今天 12:30 班次收集失败 · \<错误摘要\> ▶ 补收」/「⚠ 12:30 收集无结果」——原因透传工具错误码与消息（不做诊断），附通用排查指引；最近 10 条，agent 经 `news_schedule` `reportFailure` 回写 |
| 定时偏好已改未同步 | 定时状态行 / 编辑器同步状态行 | 「有未同步的修改」；已同步显示「已同步 · N 班次」 |
| 正在播条目 | 详情列表 + 目录弹层 | 高亮（同歌单正在播样式） |
| 空态 | 新闻页签 | 引导文案（见 §3.1） |

## 9. 明确不做（v1）

- 不做条目图片/卡片富媒体；不做条目收藏与分享；不做播报进度拖拽（讲书亦未做，按块推进）；不做面板内「立即生成」按钮（生成入口在对话框与定时班次的 ▶ 立即执行，面板做消费、回看与**定时规则配置**，见 §4）；不做多期连续连播。
