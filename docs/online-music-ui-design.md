# 在线音乐 + 网易云 VIP 登录 · 设计定稿（v2）

> 目标：在 dsh-music-player 现有播放器上叠加「在线音乐搜索播放」与「网易云扫码登录（解锁 VIP 音质）」。
> 设计原则：**贴合现有播放器交互习惯、本地优先、在线作为补充、agent 可驱动**。
>
> 状态：**搜索策略已定稿（全平台聚合）**，其余为完整设计稿。实施以 M1–M6 里程碑推进（见 §10）。

---

## 0. 设计原则

1. **不改变现有玩法**：本地曲库/歌单/讲书交互完全不动；在线只是新增一个「来源」。
2. **入口收敛**：在线功能集中在一个新的顶级 tab「在线」，不往「音乐」tab 里塞搜索框（避免与曲库/歌单子标签抢空间）。
3. **一套播放条**：在线曲目走同一个 `<audio>` 播放条与频谱，只是名称旁多一个来源标签。
4. **agent 可驱动**：`music_play` 工具本地无匹配时自动转在线搜索；播放面板只是人工浏览/搜索的补充入口。
5. **登录是「可选增强」**：默认匿名可用；登录按钮常驻但低打扰，仅解锁音质/VIP，且明确免责。
6. **多源聚合是刚需**（已实测确认）：网易云匿名搜索会把 VIP 原唱降权（翻唱顶掉原唱），**必须靠酷狗等免费源补齐**——所以搜索不是单平台，而是全平台聚合。

## 2. 搜索策略（定稿）

### 2.1 总体：全平台并发搜索 + 按歌曲身份合并

```
用户输入「晴天」→ Enter/搜索
        ↓
Host 并发搜索已启用来源：网易云(默认) + 酷狗(默认)，QQ/汽水按配置
        ↓
每个来源**独立**返回（源 A 挂了不影响源 B）
        ↓
Host 端按「歌曲身份」合并去重 → 返回聚合行
        ↓
UI 渲染聚合行（行内列出来源 chips）+ 来源级错误提示
```

### 2.2 来源清单与状态（默认）

| 来源 | 默认启用 | 匿名搜索 | 匿名播放 | VIP 登录 | 备注 |
|---|---|---|---|---|---|
| 网易云 | ✅ | ✅ | ✅ 128k（登录后 320k/无损） | ✅（扫码，已实测） | 主搜索源 + 唯一 VIP 登录源 |
| 酷狗 | ✅ | ✅ | ✅ 仅免费曲（实测 7/10） | ❌（本期不做） | 补齐网易云 VIP 原唱的免费版 |
| QQ | ⬜ 关 | ✅ | ⚠️ 少数免费曲 | ❌ | 默认关（成功率低） |
| 汽水音乐 | ⬜ 关 | ❌（需签名） | ✅（track_id/链接，64k） | ⬜ 远期 | 仅「分享链接/歌单」播放场景 |
| 酷我 / 百度 | — | ❌（实测已坏） | ❌ | — | **不展示、不启用** |

### 2.3 合并/去重算法（Host 端）

**归一化键**：`normalize(title) + '|' + normalize(primaryArtist)`

```
normalize(s):
  1. 去首尾空白、全角→半角（如 Ａ→A，：→:）
  2. 全部转小写
  3. 去掉尾部「版本修饰」标记（循环剥除，最多 3 层）：
     (Live) / 现场版 / 翻唱 / cover / DJ版 / Remix / 钢琴版 / 吉他版 /
     深情版 / 女声版 / 男声版 / 原唱:xxx / feat.xxx 等
  4. 去掉书名号、引号、括号
```

**合并规则**：
- 同键 → 合并为一行；每个来源只保留该来源内「可播性+音质」最优的一条。
- 行内字段：`{ key, title(取最完整的), artists[], album, sources: [{source, songId, br, playable, vip, urlKey}] }`。
- **不合并**：主歌手不同（同名异曲、翻唱 vs 原唱）；Live/翻唱等版本标记剥除后标题不同的。

**排序（行与行）**：
1. 可免费播放 > VIP（已登录可播）> VIP（未登录）
2. 同档：音质高 > 低
3. 再按相关度（各来源排名的 min 值）

**行内默认来源（best-available）**：
- 已登录：网易云 VIP 320k/无损 > 匿名 128k > 酷狗免费
- 未登录：酷狗免费 > 网易云 128k > VIP（不可播，标注）
- 播放失败时按同键其余来源降级，再失败才试下一行。

### 2.4 agent（music_play）的确定性选曲策略

优先级（从高到低，取第一个满足的）：
1. **可免费播放**（匿名 playable）
2. **原唱匹配**：query 含歌手名时，结果歌手列表与其匹配（避免播到翻唱）；query 无歌手名则跳过此项
3. **音质 br 高**
4. **已登录 VIP**（同曲 VIP 320k > 匿名 128k）
5. 首选播放失败 → 同键换源 → 下一行

## 3. 各区块 UI 设计

### 3.1 顶部 tab

沿用现有 `dsh-music-tab` 样式，三栏均分：`[音乐] [在线] [小说]`。
- `s.tab` 增加 `'online'`；正在播放在线曲目时打开面板自动切到「在线」tab。

### 3.2 在线 tab 布局（核心区）

```
┌──────────────────────────────────┐
│ 在线播放 [●]         [网易云登录 ▾] │ ← ① 总开关 + 登录入口
├──────────────────────────────────┤
│ [🔍 搜歌曲 / 歌手 / 专辑 …]  [搜索] │ ← ② 搜索输入（Enter 触发）
├──────────────────────────────────┤
│ (自动)(网易云)(酷狗)  · 未登录      │ ← ③ 来源 chips + 账号状态
├──────────────────────────────────┤
│  ▶ 晴天 · 周杰伦          [网易云][酷狗]│ ← ④ 聚合结果行
│    七里香 · 周杰伦              [VIP]│ ← 行内来源/可播标签
│    …                            │
├──────────────────────────────────┤
│  （提示区：搜索中/空/部分失败/翻唱…）   │ ← ⑤ 内联提示
└──────────────────────────────────┘
```

**① 在线播放总开关**：面板右上小开关（`--dsh-music-accent` 激活色），默认关。关闭时「在线」tab 只显示一行说明，**不发起任何外部请求**（隐私/合规）。

**② 搜索输入**：占满宽度；Enter 或「搜索」按钮触发，**不做每键即时搜索**（防风控）。二次搜索用 requestId 丢弃过期结果（见 §7-S7）。

**③ 来源 chips（单选）**：
- `(自动)`：默认——并发搜索网易云 + 酷狗，聚合展示
- `(网易云)` / `(酷狗)` / `(QQ)`：限定单平台
- 选中高亮 accent；不可用来源（酷我/百度）不展示。
- 右侧账号状态：未登录 `未登录 [登录]`；已登录 `♪ {昵称} [退出]`。

**④ 聚合结果行**（复用 `.dsh-music-track`）：
```
▶ 晴天
  周杰伦 · 叶惠美          [网易云 128k] [酷狗 320k]
```
- 主信息：歌名（播放中加 `▶`）；次行：歌手 · 专辑。
- 行尾：该行**全部可用来源**的 chip；chip 内显示该来源音质/可播性。
- 点击 chip → 用该来源播放（可播性差的 chip 置灰并说明原因）。
- 行点击 → 用行内 best-available 来源播放。
- VIP 标签：`VIP`（未登录，点击弹登录引导）/ `320k` / `无损` / `64k`。

**⑤ 内联提示区**：见 §7 场景表，按状态显示。

### 3.3 网易云登录模态

复用 `.dsh-music-picker-overlay` + `.dsh-music-picker` 视觉：

```
┌ 网易云音乐登录 ───────────────[✕] ┐
│        [ QR 码 ]                │ ← unikey 本地生成
│  使用「网易云音乐」App 扫码       │
│  ① 打开 App → 右上角扫一扫       │
│  ② 在手机上确认登录              │
│   ⏳ 等待扫码…                  │ ← 轮询状态机
│      [ 取消登录 ]                │
│  免责声明：第三方接口登录存在      │
│  账号风控风险，请知悉并自担风险。  │
└───────────────────────────────┘
```

登录状态机见 §6.3；QR 用一个内联 MIT QR 编码器（~6KB）生成，内容 `https://music.163.com/login?codekey=<unikey>`（已实测）。

### 3.4 播放条集成（在线曲目）

- 名称旁来源 chip：`♫ 晴天 · 周杰伦 [网易云]`（复用 `.dsh-music-bar-section` 样式）。
- 在线曲目**不进入**曲库/歌单；**♥ 收藏按钮隐藏**（在线无稳定文件路径，后续做「在线收藏表」）。
- 在线播放错误：播放条显示「在线音频已失效，正在重新获取…」→ 自动重取一次 → 仍失败红字 + 「换源」按钮（同键其他来源）。
- 播放时面板行高亮、来源 chip 高亮。

## 4. 数据模型

### 4.1 搜索响应（Host → 前端）

```
POST /dsh-music/online/search { query, sources?: ['netease','kugou'] }
→ 200 {
  requestId, query,
  groups: [                       // 聚合行
    { key, title, artists: [...], album,
      sources: [
        { source, songId, br, playable, vip, urlKey }   // urlKey = `${source}:${songId}`
      ],
      best: 'netease' }           // 默认来源
  ],
  sourceStatus: { netease: 'ok', kugou: 'degraded', ... },
  sourceErrors: { kugou: '接口暂不可用' },
  ttl: 600
}
```

### 4.2 播放响应

```
GET /dsh-music/online/play/<urlKey>      // Host 换真实 URL 并流式代理
→ 200 audio/mpeg|audio/mp4 流
→ 4xx JSON 错误码：
   { error: 'VIP_REQUIRED' | 'URL_EXPIRED' | 'SOURCE_UNAVAILABLE' | 'RATE_LIMITED' | 'NETWORK' , message }
```

### 4.3 网易云登录

```
POST /dsh-music/netease/login/start                 → { unikey, qrContent }
POST /dsh-music/netease/login/check { unikey }      → { state: 'waiting'|'scanned'|'ok'|'expired', nickname? }
GET  /dsh-music/netease/login/status                → { loggedIn, nickname, vip }
POST /dsh-music/netease/login/logout                → { ok }
```

### 4.4 Host 侧状态（内存 + 持久化）

| 数据 | 位置 | TTL | 说明 |
|---|---|---|---|
| 搜索缓存（按 query+来源） | 内存 LRU | 10 min | 命中直接返回，减请求 |
| 播放 URL 缓存（按 urlKey） | 内存 | 30 min | 网易/酷狗 URL 带时效 token |
| 平台 cooldown（429/空响应） | 内存 + localStorage | 5 min | 风控退避 |
| 网易云 cookie | `~/.dsh/music-player-netease-cookie.json` | 持久 | 0600 权限、仅 Host 读写 |

## 5. 关键交互流程

### 5.1 人工搜索并播放

```
输入 → Enter → POST /online/search（requestId 递增）
→ 并发搜索各源 → 合并 → 渲染聚合行 + 来源状态
→ 点击行/来源 chip → GET /online/play/<urlKey>
→ Host 换真实 URL → 流式回传 → <audio> 播放 + 来源标签
失败分支：VIP 未登录 → 登录引导；URL 失效 → 自动重取/换源（§7-P2/P3）
```

### 5.2 网易云登录

```
点登录 → 模态 → start 拿 unikey → 渲染 QR → 每 3s 轮询 check
→ 801 等待 → 803 已扫码 → 200 成功（Host 捕获 Set-Cookie 持久化）
→ 关模态 → 状态行「♪ 昵称」→ 之后搜索/播放走 VIP cookie
异常：800 过期 → 重新生成；取消 → 停轮询（§7-L1..L7）
```

### 5.3 agent 播放

```
music_play(query, source?)
→ 本地曲库匹配 → 命中则本地播放（不变）
→ 无匹配 → 在线搜索（自动/指定源）→ 按 §2.4 确定性选曲
→ pendingIntent { kind:'online', urlKey, name, source } → 浏览器播放
→ 回复注明来源与音质；若播了翻唱/降级 → 在回复中说明
```

## 6. 状态机

### 6.1 搜索状态机

```
idle ──(输入+Enter)──▶ searching ──▶ success        （全部/部分来源成功）
                        │  ├─▶ partial   → 提示"某来源暂不可用"
                        │  ├─▶ empty     → 空态
                        │  ├─▶ error     → 全部失败
                        │  └─▶ timeout   → 超时 + 重试
                        └──(新搜索)→ searching（requestId 作废旧结果）
```

### 6.2 播放状态机（在线曲目）

```
resolving ──▶ playing ──▶ ended
              │  └─(URL失效/403/断流)→ retrying(重取一次)
              │                        ├─▶ playing（成功）
              │                        └─▶ fallback(同键换源) ──▶ playing | 失败提示
              └─(VIP 未登录)→ 登录引导
```

### 6.3 登录状态机

```
closed ──▶ generating ──▶ waiting(801) ──▶ scanned(803) ──▶ logged_in(200)
                          │                 │
                          ├─▶ expired(800)──┴─▶ regenerating ──▶ waiting
                          └─(取消/关闭)──▶ closed
```

## 7. 场景与异常处理大全

### 7.1 搜索阶段

| # | 场景 | 处理 |
|---|---|---|
| S1 | 全部来源不可用 | 错误态 + 建议稍后；不显示空列表 |
| S2 | 部分来源可用 | 正常显示可用来源结果；提示区「酷狗接口暂不可用，已只显示网易云」 |
| S3 | 单平台被风控（连续空/429） | 该来源进 cooldown（5min），自动剔除重试；UI 标注该源「暂时不可用」 |
| S4 | 网络断开 | 提示「网络不可用，请检查连接」；重试按钮 |
| S5 | 无结果 | 空态「没有找到相关歌曲，换个关键词试试」 |
| S6 | 搜索超时（>10s） | 提示超时 + 重试；部分已返回的来源仍展示 |
| S7 | 用户连续搜索 | requestId 递增，只渲染最新；旧请求结果直接丢弃（防结果错乱） |
| S8 | 输入为空/过短（<1字） | 前端拦截，不发起请求 |
| S9 | 同歌多平台重复 | 合并成一行（§2.3） |
| S10 | 同名不同歌手 | 不合并（键含歌手） |
| S11 | 翻唱 vs 原唱 | 不合并；agent 场景按歌手匹配优先原唱，否则提示「已播放翻唱（{歌手}）」 |

### 7.2 播放阶段

| # | 场景 | 处理 |
|---|---|---|
| P1 | VIP 曲未登录 | 行 chip 置灰 `VIP`；点击 → 登录引导（不硬播）；agent 自动换免费源 |
| P2 | URL 过期/404（播放中） | 自动重取一次（新 URL）→ 仍失败 → 同键换源 |
| P3 | CDN 防盗链 403 | 判定不可播 → 换源；多次 403 → 该源 cooldown |
| P4 | 播放中途断流/网络波动 | `<audio>` error → 提示「播放中断」+ 重试 |
| P5 | 平台封 IP（大量失败） | 该源 cooldown + 提示「来源暂时不可用，已自动切换」 |
| P6 | 目标音质拿不到 | 自动降档（如 320→128），标签显示实际音质 |
| P7 | DRM 加密曲目（汽水 spade 等） | 本期不支持 → 标注「加密曲目不可播」→ 换源 |
| P8 | 浏览器自动播放被拦截 | 沿用现有「点一次▶解锁」流程（与本地一致） |
| P9 | 已登录但 cookie 失效 | 播放/搜索返回会话过期 → 提示「登录已失效，请重新登录」→ 清 cookie 状态 |
| P10 | 在线曲目与本地/歌单混播 | **严格隔离**：在线曲目不参与曲库/歌单循环；停止/切曲逻辑不变 |

### 7.3 登录阶段

| # | 场景 | 处理 |
|---|---|---|
| L1 | start 拿 unikey 网络失败 | 模态内提示 + 重试 |
| L2 | 二维码 800 过期 | 「二维码已过期」+ 重新生成按钮 |
| L3 | 扫码后未确认（803 卡住） | 持续等待，给「取消」；提示「请到手机上确认」 |
| L4 | 登录成功但拉账号信息失败 | 仍视为登录成功（cookie 已存），昵称显示「已登录」 |
| L5 | 已登录再点登录 | 显示当前账号 + 「退出登录」；不重复扫码 |
| L6 | cookie 文件损坏/不可读 | 视为未登录，可重新扫码 |
| L7 | 首次登录 | 先弹免责确认（风控/ToS 风险）再出二维码 |
| L8 | 登录并发（多标签页） | 以最后成功者为准；退出清空 |

### 7.4 缓存/一致性

| # | 场景 | 处理 |
|---|---|---|
| C1 | 搜索缓存命中 | 直接返回（TTL 10min） |
| C2 | URL 缓存过期 | 重新取链（TTL 30min，匹配实测时效） |
| C3 | 并发相同查询 | 合并请求/短路（同一 query 只打一次上游） |
| C4 | 平台 cooldown 跨刷新 | 持久化到 localStorage，刷新后仍退避 |
| C5 | 来源列表/可用性变化 | 每次搜索后刷新 sourceStatus 并缓存，chips 据此显示 |

### 7.5 隐私/合规

| # | 场景 | 处理 |
|---|---|---|
| V1 | 在线开关关闭 | 不发起任何外部请求（默认态） |
| V2 | 匿名搜索/播放 | 仅发匿名请求头；无账号信息 |

## 10. 决策记录

**已确认：**
1. 「在线」为**顶级 tab**（非音乐 tab 子区）。
2. 搜索策略 = **全平台并发搜索 + 按歌曲身份合并**（默认网易云 + 酷狗；QQ/汽水默认关）。
3. agent 用确定性「best-available」选曲策略（§2.4）。
4. 搜索 Enter/按钮触发，不做即时搜索。
5. 登录入口在「在线」tab 状态行。
6. 在线曲目不进曲库/歌单、♥ 收藏隐藏（后续做「在线收藏表」）。
7. 酷狗/QQ 本期不做 VIP 登录（文档标注）；汽水仅分享链接场景。

**待实现时再定的小项：**
- 聚合行在「来源很多」时的 UI 折叠策略（>3 个 chip 折叠为「+N」）。
- 搜索历史（是否要「最近搜索」列表，简单实现可加）。
